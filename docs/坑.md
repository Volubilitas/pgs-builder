# 坑清单（都踩过、都修了、都有实测）

> 每条的格式：**症状 → 原因 → 修法**。按"从上游到下游"排（渲染 → 量化 → 位流 → 封装 → 验收工具）。

## 1. ffmpeg 没有 PGS 编码器（这条不是 bug，是前提）

- **症状**：`ffmpeg -i x.ass -c:s hdmv_pgs_subtitle out.sup` → `Unknown encoder` / `Encoder (codec hdmv_pgs_subtitle) not found`；
  `ffmpeg -h encoder=hdmv_pgs_subtitle` → `Codec ... is known to FFmpeg, but no encoders for it are available`；
  `ffmpeg -encoders` 全表里没有它（测过 5 个构建，含 SubtitleEdit 自带的）。
- **原因**：ffmpeg 有 `sup` 封装器、有 `pgssub` 解码器，**从来没有编码器**；ffmpeg 里也没有"视频帧 → AVSubtitle"的通路
  （`-filters` 里没有任何字幕类滤镜，无 `->S` / `S->`）。退一步用 `dvdsub/dvbsub/xsub` 也不行：它们只支持
  bitmap→bitmap（`Subtitle encoding currently only possible from text to text or bitmap to bitmap`），
  而 `sup` 封装器只收 `hdmv_pgs_subtitle`。
- **修法**：自己写位流写入器（本工程）。ffmpeg 只当**渲染器**和**独立验收器**用。

## 2. `alpha=1` 的 alpha 通道只有真实 α 的 63%

- **症状**：整条字幕被系统性压暗到 2/3，且"看不出哪里错"（各 α 档一致偏低，不是个别像素）。
- **原因**：ASS 渲染器输出的 α 不等于播放器合成用的 α。
- **修法**：**两趟黑白渲染反解**：`B = c·α`、`W = 255(1−α) + c·α` ⇒ `α = 1 − (W−B)/255`、`c = B/α`；
  第三张灰底独立验证 99.8%。见 `gen_pgs.solve_ca()`。

## 3. 用「整帧 RMSE」验收字幕 = 看不见问题

- **症状**：三档不同口径的字幕，整帧 RMSE 只差 3%，"都合格"；实际上字幕层差得很远。
- **原因**：字幕只占画面千分之几（实测覆盖率 0.16%），误差被背景吃掉。
- **修法**：口径必须换成 ①**预乘空间、只比字幕层**的 RMSE；②**Σα 保真比**；③**解码帧的 α 档位数**。
  `验收PGS.py` 就是这三条。同一类错误还坑过 RLE 解码器的 bug（见 18）。

## 4. `duration=DURATION` 写成函数默认参数 ⇒ 无限渲染

- **症状**：明明 `--frames 150`，ffmpeg 却一直读下去（实测 2.5 s 的窗口读到 3000+ 帧）；`-t` 像没生效。
- **原因**：默认参数在**模块导入时**求值，命令行后来改 `DURATION` 不影响已绑定的默认值 ⇒ lavfi 的 `color` 源是无界的，
  不给 `-t` 就永远有帧。
- **修法**：签名写 `duration=None`，函数体内 `if duration is None: duration = DURATION`（`encode()` 同样处理）。

## 5. 靠 ffmpeg 的 `select` 滤镜抽样建板不可靠

- **症状**：抽样间隔改了不生效，静默变成"全帧放行"，建板奇慢。
- **原因**：`select` 表达式一旦不生效不会报错；与坑 4 叠加更危险（源无界）。
- **修法**：**按上限渲染 + 在 Python 侧抽样**（每 `--step` 秒取一帧），行为完全可预测。

## 6. 不给长度就无限跑（lavfi 无界源）

- **症状**：只想编 5 秒，结果跑了十几分钟；日志里"帧数"一直涨。
- **修法**：CLI 不给 `--frames/--duration` 时，**自动读 ASS 最后一条 Dialogue 的结束时间**定长
  （`ass_end_time()`，留 0.5 s 余量）；读不出来就报错退出，不猜。

## 7. RLE：每一行必须写满对象宽度

- **症状**：ffmpeg 报 `Insufficient RLE data`；OpenGL/硬件解码器干脆整帧不显示。
- **原因**：EOL（`00 00`）只推进行号、**不补像素**，而解码器用全局 `pixel_count` 校验 `w×h`。
- **修法**：每行（含全透明行）显式写满宽度，行尾透明像素并入最后一个游程。见 `pgsenc.rle_row()`。

## 8. ODS 段长 65535 边界：判据少算了段头 7 字节

- **症状**：全片编到**第 12240 帧**炸：`struct.error: 'H' format requires 0 <= number <= 65535`。
- **原因**：ODS body 实际是 `len(rle) + 11`，判据却写成 `len(rle) + 4` ⇒ `len(rle) ∈ [65525, 65531]` 走了不切片分支。
- **修法**：判据改 `len(rle) + 11 <= 65535`；超限按 65000 字节切片，`seq` 标志 `0x80` 首 / `0x00` 中 / `0x40` 尾。
  （4K 上这条路径会真的走到：4K60 示例 300 帧触发 95 次分片。）

## 9. PCS `comp_state = 0x40` 会拖影

- **症状**：细颗粒/点阵字幕每帧把**上一帧的对象也画出来** ⇒ 灰色拖影（实测解码帧像素数正好翻倍）。
- **原因**：`0x40` = acquisition point（合成不完整，解码器要保留之前的对象再叠加）。
- **修法**：首个 set 用 `0x80`（epoch start），其余一律 `0x00`（normal，本 set 即完整合成）。
  本工程每个 set 都自带完整调色板与唯一对象，所以 `0x00` 是正确语义。

## 10. 字幕消失时别忘了**擦除集**

- **症状**：最后一句台词结束后，最后一张字幕一直挂在画面上（尤其播放器暂停/跳转时）。
- **修法**：上一帧有内容、本帧没有内容时，发一个 `n_obj = 0` 的空 display set；片尾再补一个。
  `验收PGS.py` 会把这种"末尾多出来的 set"标出来（PCS 数 > 有对象的组数）。

## 11. `-ss` 放在 `-i` 之前会把 PTS 归零 ⇒ 字幕/叠加滤镜什么都渲不出来，而且不报错

- **症状**：抽单帧检查字幕效果，图里没有字幕，**日志没有任何报错**。
- **原因**：`-ss` 在 `-i` 前 = 输入 seek，时间戳从 0 重新计；`subtitles`/`overlay` 这类按 PTS 取内容的滤镜看到 t≈0。
- **修法**：抽帧验证时加 `-copyts`。

## 12. `-filter_complex` 与 `-map 0:v` 同时用 = 把原流也映射出去

- **症状**：`Function not implemented` / `No filtered frames for output stream` / `Could not open encoder before EOF`。
- **原因**：既有滤镜图输出、又把 `0:v`（hw frame）原样映射进输出，编码器拿到它解不了。
- **修法**：只留 `-map "[标签]"`。本工程在"垫一条已有 PGS"的模式里就是这么写的。

## 13. 用 ffmpeg 解 `.sup` 验收时的两个硬要求

- **症状 A**：`ffmpeg -i in.sup -f rawvideo -pix_fmt bgra -` → `Output file does not contain any stream`。
  **修法**：必须走滤镜图，例如 `-filter_complex "[0:s]scale=iw:ih[p]" -map "[p]"`。
- **症状 B**：帧数对不上（120 帧只出 52 帧）。
  **修法**：不给 `-r` 会按 25 fps 出，必须显式 `-r 60`（或与轨一致）。
- 顺带：`.sup → -c:s copy → mkv → -c:s copy → .sup` 字节级一致 ⇒ 封装无损。

## 14. mkvmerge 默认给字幕轨做容器内 zlib 压缩 ⇒ 部分电视/手机上**字幕整体消失**

- **症状**：PC 上一切正常，电视/盒子/手机上画面正常、**字幕没有**（不报错）。
- **原因**：mkvmerge 默认对字幕轨做 zlib `ContentEncodings`；部分播放器的原生解复用器不认，静默丢轨。
- **识别**：`mkvmerge -J` 看 **`content_encoding_algorithms`**（空 = 没压，`"0"` = zlib）。
  ⚠️ 别查 `content_encodings` 这个键——它不反映压缩，会让你误判"没压"。等价的字节特征：Tracks 元数据里
  `6d 80 86 | 62 40 83 | 50 34 80`（ContentEncodings → ContentEncoding → ContentCompression，算法字段缺省 = 0 = zlib）。
- **修法**：给**每条字幕输入**加 `--compression 0:none`。⚠️ 它的作用域是**紧跟其后的那个输入文件**，位置放错就不生效。
  代价：同一条 PGS 从 597,915,564 B 回到 1,060,748,478 B（+0.42 GB）。
- **判据**：**"位流写对了"不等于"交付对了"** —— 封装参数能让成品在电视上整体消失。

## 15. mkvmerge 的两个小坑

- `mkvmerge -i` **不打印 default/forced 标志** ⇒ 判断"哪条轨是默认轨"要另找办法（`-J` 的 `properties.default_track`）。
- `0:s:N` 是"第 N 条字幕轨"的**相对序号**，不是轨道 ID ⇒ 混流/抽取前先 `mkvmerge -i` 看清单。

## 16. 输出路径写在输入目录 = 覆盖源文件

- **症状**：跑完一次，源 ASS/源 .sup 变成了产物。
- **修法**：产物一律换目录/换名；脚本里不要用"同名同目录"的默认输出。

## 17. 自写 vint 解析器遇到首字节 `0x00` 会死循环

- **症状**：探针脚本"跑得特别慢"，其实是卡住了（`while not (b0 & m)` 里 m 右移到 0 之后恒真）。
- **修法**：PGS **段头是定长 13 字节**（`PG` + PTS4 + DTS4 + 类型1 + 长度2 BE），根本不需要 vint 解析；
  真要用 EBML vint，必须对首字节 0 设防（EBML 里 0x00 是非法 vint）。

## 18. 验收用的解码器自己有 bug ⇒ 验收结论全错（本项目最贵的一课）

- **症状**：往返"整帧 RMSE 2.1"看着很好；实际上解码器把**所有长度 ≥2 的同色 RLE 游程全丢了**。
  实测写侧 328,619 个非零像素 → 解回来只剩 5,043 个（正好是孤立单像素）。
- **原因**：`00 10LLLLLL C` / `00 11LLLLLL LL C` 两个分支只做了 `x += n`，把颜色字节 C 当"跳过"。
  它躲过历次验收正是因为**口径**（坑 3）：字幕覆盖 0.16%，整帧 RMSE 看不见。
- **修法**：修 `rle_decode`；**验收解码器必须用"填满的图形（长游程）"**，不能用稀疏点阵。
  现在示例字幕里专门放了矢量图形 + 12 档 α 阶梯，就是给这类 bug 用的。

## 19. `.sup` 与封装后的 PGS 轨时间戳差 +0.333 ms（正常，不是错）

- **现象**：从成片 `mkvextract` 出来的 `.sup` 与编码器直接产出的 `.sup` 大小完全相同、**显示集逐字节相同**，
  只有 4 万多个时间戳字节不同 —— 每段都恰好差 **+30 个 90 kHz 刻度 = +0.333 ms**。
- **原因**：Matroska 的时间基是 1 ms，mkvmerge 会把 90 kHz 的 PTS 量化到毫秒。
- **结论**：相对 16.7 ms 的帧间隔无意义；**成片自带的 PGS 就是全片 `.sup` 的完整副本** ⇒ 全片 `.sup` 属于可弃中间件。

## 20. Windows 路径进 ffmpeg 滤镜

- **症状**：`ass='D:\a\b.ass'` 报滤镜解析错（冒号被当参数分隔符）。
- **修法**：正斜杠 + 转义冒号 + 单引号包裹：`D\:/a/b.ass`，即 `ass='D\:/a/b.ass'`。
  本工程由 `gen_pgs._ass_filter()` 统一处理（含 `fontsdir`）。

## 21. `--step` 默认 1.0 秒 ⇒ 吃默认值会**过不了自己的验收**

- **症状**：同一条字幕、同一块画布、同一段帧数，只因为没显式给 `--step`，往返 RMSE 就是 **8.670**（判据 < 8 ⇒ **FAIL**）；
  显式给 `--step 0.05` 后是 **1.556**。
- **原因**：`--step` 是**建板抽样密度**；调色板是从抽样帧的颜色里切出来的，抽样太稀 ⇒ 板覆盖不到全部帧的颜色。
- **修法**：按内容显式给 `--step`（本仓库示例 0.05~0.25）。代价几乎只有建板时间（120 帧：2.8 s → 17.3 s），
  `.sup` 体积几乎不变（4.69 → 4.76 MB，+1.5%）—— 完整实测曲线见 README"建板抽样密度"一节。
- ⚠️ 推论：**任何"默认参数"都要在自己的真实素材上量一遍**，别假设"默认 = 安全"。

## 22. 单帧读数被当成整段读数引用（口径混用的第二种）

- **症状**：文档表格里写"120 帧往返 RMSE 0.712"，可照着命令复现出来是 1.5~4.0，怎么调都对不上。
- **原因**：0.712 其实是**效果图图头印的单帧（第 45 帧）**读数，被抄进了"整段 120 帧均值"那一格；
  两者差一个数量级很正常（单帧只挑了一帧，而那一帧恰好最干净）。同类错误见坑 3。
- **修法**：**每个数字都标口径**（单帧 / 整段均值 / 中位 / p95，以及帧数）。本仓库现在的规矩：
  表格里只放"整段均值 + 判据"，单帧数字只出现在效果图图头，并在 README 里明写"别混用"。
